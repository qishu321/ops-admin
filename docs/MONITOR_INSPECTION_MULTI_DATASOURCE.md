# 多数据源巡检

2026-10-26，适用于 `/monitor/inspections`。一套巡检方案可同时选择多个 Prometheus / VictoriaMetrics 数据源，逐源执行全部启用规则，保存为一份巡检报告。

## 使用行为

- “巡检数据源”支持多选、搜索，至少选择一个；清空选择不会偷偷回退到默认数据源。打开方案时会从最近一次报告恢复仍有效的数据源选择。
- 选择数据源、时间范围不会自动发起指标查询。点击“执行巡检”后，按“数据源数 × 启用规则数”生成结果。
- 每条结果标明数据源，可同时按数据源和状态筛选；统计数量随报告筛选变化。相同巡检项在多个数据源下有独立结果标识。
- 编辑/删除按钮操作原始规则，避免把某个数据源的报告快照当成规则定义。
- PDF包含整份报告的数据源名称和全部结果，不受当前页面的结果筛选影响；报告文字及数据源名称均进行HTML转义。

## 接口与执行

`POST /api/v1/monitor/inspection/run` 新增 `datasourceIds`：

```json
{
  "dashboardId": 10,
  "datasourceIds": [1, 2],
  "startAt": 1792998000,
  "endAt": 1793001600,
  "stepSeconds": 15
}
```

- 数组优先，按顺序去重；兼容旧 `datasourceId` 请求以及未指定数据源时的旧规则默认值。显式提供但全为无效ID的数组会报错。
- 执行前校验每个数据源的查询权限、启用状态和指标类型；参数/权限不通过时不发起任何指标查询。
- 全部数据源共用4个查询worker，每次指标查询仍有30秒超时。单个查询失败保存为对应数据源的异常结果，其他查询继续；无数据沿用规则自身的无数据策略。
- 浏览器等待时间根据所选数据源与启用规则数量估算，避免沿用通用15秒请求超时导致多源巡检已在后台执行、页面却先报失败。
- 界面防止重复提交，执行和读取历史报告的迟到响应不能覆盖另一方案；旧服务端若只返回单源报告，界面会提示更新后端，不把它当成多源成功结果。

## 报告存储与升级

- `monitor_inspection_run` 新增 `datasource_ids`、`datasource_names`，以JSON序列化字段存储本次选择及名称快照。
- `monitor_inspection_result` 新增 `datasource_id`、`datasource_name`，每条结果保留所属来源。
- 旧单源头字段保留。旧报告读取时从头字段补齐结果的数据源信息，不改写历史记录；数据源改名不会改变已保存的报告。
- 历史报告读取同样校验该报告所有数据源的查询权限。
- 两个模型已在现有 `store.AutoMigrate` 列表中。更新并启动后端时自动增加字段，之后加载更新后的前端。未手动执行线上DDL，也未重启当前服务。

## 文件

- `backend/model/monitor.go`：报告头及结果的数据源快照字段。
- `backend/service/monitor.go`：一次巡检跨数据源展开、共用并发池、总数统计和结果持久化。
- `backend/service/monitor_inspection_sources.go`：来源去重/校验/授权、旧报告来源补齐。
- `web/src/views/monitor/dashboard/composables/useInspection.js`：多选状态、报告还原、结果复合标识及筛选。
- `components/inspection/InspectionToolbar.vue`：多选与时间窗口、执行入口、主题与导出操作；`InspectionView.vue`编排报告总览和结果列表。
- `useInspectionExport.js`：完整多源PDF；`web/src/api/monitor.js`：支持巡检请求单独设置等待时间。

## 巡检界面改版（2026-10-26）

### 设计与实际完成

原界面把通用监控工具条、报告元信息、状态筛选、执行按钮、PromQL宽列叠放在多层容器中。结论不突出，查询列占用大量横向空间，窄屏只能看到规则名和固定操作列。

- 执行配置集中在独立工具条：多选数据源、预设/自定义时间、执行按钮、启用规则数量；导出报告、添加规则和主题切换作为次级操作。
- 报告总览直接显示本次结论、检查总数及三类状态数量，保留报告编号、完整窗口、完成时间与耗时。统计卡点击后筛选结果。
- 数据源卡片按已保存的结果分别汇总，显示正常/待核查/异常分布；点击卡片筛选该来源，再次点击取消。未知或缺失结果不会被标成全部正常。
- 总览始终统计完整报告，明细筛选不会改变报告总数；配置变更也不会修改旧报告快照。
- 桌面结果表保留来源、状态、数值/序列和判定规则，异常优先；PromQL和错误详情放入可展开行，减少常态下的表格宽度。
- 760px及以下改为逐项结果卡片，直接显示来源、状态、数值和阈值，并可展开查询详情、编辑和删除规则。仅挂载表格或卡片其中一种，避免大报告生成双份结果DOM。
- 补充未生成报告引导、无匹配结果空态和重置筛选入口。保留执行加载遮罩、禁用条件、原规则编辑/删除及完整报告PDF导出逻辑。
- 监控网格继续使用原工具条；本次配色和控制样式限定在`.is-inspection-page`内。

视觉规范：浅色画布`#f4f7fb`、白色表面、正文`#172740`、辅助文字`#66758a`、靛蓝操作色`#4e60ce`；暗色画布`#0d1522`、表面`#141f2f`、正文`#e7edf6`。状态使用独立绿/琥珀/红，图标和文字共同标识状态。标题25px、结论20px、主要数值30px、正文12–14px；主区间距16–26px、容器圆角14px、细描边和轻阴影。使用系统中文字体和等宽查询字体，不加载外部字体或新增运行时依赖。键盘焦点可见，减少动态效果偏好下关闭过渡。
