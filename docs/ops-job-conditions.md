# 作业条件分支

在步骤库添加“条件分支”，将一个脚本或文件步骤连接到它，再从“满足条件”和“不满足”两个出口分别连接后续步骤。每个出口必须且只能有一条连线。

## 条件配置

- 判断来源：直接连接到条件的前置脚本或文件步骤。
- 执行状态：全部成功、部分失败、全部失败；支持等于、不等于。
- 成功或失败主机数：支持等于、不等于、大于、大于或等于、小于、小于或等于；比较值为非负整数。
- 主机统计来自该次执行的任务记录，不读取当前主机状态，也不解析脚本输出。
- 前置步骤在创建主机执行任务之前就失败时，不存在主机统计；此时只能判断执行状态。统计不存在会明确报错，不会当作零。

```json
{
  "id": "check-result",
  "type": "condition",
  "label": "健康检查是否通过",
  "config": {
    "sourceStepId": "health-check",
    "field": "status",
    "operator": "eq",
    "value": "success"
  }
}
```

条件出边携带 `branch: "true"` 或 `branch: "false"`。普通步骤的出边不携带此字段。

## 失败处理

脚本和文件步骤默认保持失败即停止。需要检查失败结果时，将前置步骤的“失败时”设置为“进入后续条件分支”（`failurePolicy: "branch"`）。其所有直接后续步骤必须是判断该步骤的条件分支，后端在保存和执行前校验。

失败记录不会被覆盖为成功。作业完成异常分支处理后，整体显示“完成（存在失败步骤）”（`partial`），防止把发布或检查失败误报为全部成功。人工确认拒绝和条件本身配置、读取结果失败仍会终止作业。

## 选择、汇合和恢复

- 条件只启用一个出口，未启用路径上的步骤记录为 `skipped`，不会执行其脚本、文件、通知或人工确认。
- 汇合节点在所有前置路径都已处理后，只要至少有一条启用的路径到达就执行一次；全部前置路径被跳过则继续跳过。
- 嵌套分支通过在某条路径上再接脚本或文件步骤及条件节点实现。
- 每次判断的结果保存在步骤历史的可空 `branch_result` 字段；空值表示没有判断结果，`false` 表示明确选择“不满足”，两者不同。
- 人工确认恢复使用该次执行保存的定义、结果和分支选择；不会重新执行已完成步骤，也不会重新判断已选分支。
- 审批通过、拒绝通过数据库事务和状态条件更新实现互斥，重复提交不会重复启动恢复任务。

无条件节点的旧作业保持原来的顺序和普通多出边行为。条件判断不引入并行调度或任意表达式执行。

## 发布

本功能需要同时更新前后端。后端启动时的现有自动迁移会为 `ops_job_history_step` 添加可空的 `branch_result` 字段。旧记录不需要回填。
