# 用户组与资源授权

系统管理收敛为四个入口：用户管理、用户组、访问策略、系统设置。角色和资源授权归并到访问策略工作台；菜单维护位于系统设置的高级设置中。仅平台管理员维护这些配置。

## 使用方式

1. 在用户管理中创建普通成员，选择其所属用户组；不再选择部门、岗位或必选角色。
2. 在用户组页面组织协作成员。同一用户可加入多个组，用户组与主机组分别管理人员和资源。
3. 在 `/system/access-policies` 新增策略，依次配置策略名称、授权对象、资源范围与操作。功能入口随新策略自动开放，无需再分配一遍角色菜单。
4. 可选择权限模板作为起点，复制对应资源类型的操作后继续调整。在策略表单中复制模板后，模板后续变更不会联动修改该策略；平台管理员身份不通过资源模板授予。
5. 在“用户有效权限”选择用户，核对个人策略、组继承、已停用账号和全局只读限制。用户表格也提供权限预览入口。

兼容模板页保留原有角色配置。已关联旧角色的账号继续使用原来的功能权限；编辑账号资料或用户组不会替换旧角色。旧资源授权使用 `unified=false`，继续受原角色功能权限约束；新策略使用 `unified=true`。为测试实例新增终端或写权限，不会因此放开旧生产实例授权中原来被角色限制的操作。编辑旧授权时，界面提示保存会转为统一策略。

停用策略或用户组、移出成员、撤销策略，会在后续请求重新计算权限时生效。若账号具备平台预置全局只读角色，该限制继续作用于新策略。

个人授权与所有启用用户组的授权叠加，不设置互相覆盖的拒绝规则；查看权限随授权保留，终端、查询、上传等操作独立勾选。已建立的终端及已接收的异步任务不会被这次变更强制中断。

## 授权后的自动同步

后端每次请求都会重新计算权限。登录与个人资料接口返回 `accessRevision`，它包含功能权限、资源范围、主机组展开结果和只读限制的稳定摘要，不包含凭据。只增加资源范围、未改变页面权限时，也会产生新版本。

前端在路由切换、窗口重新获得焦点、页面恢复可见时同步个人资料；可见页面还会每 15 秒检查一次。版本变化后，在原页面更新主机列表、主机组、SSH 资源树、K8s 集群列表及概览，并恢复或隐藏相应操作按钮；保留筛选条件，不重建已打开的终端。隐藏的缓存页面在再次激活时刷新。

主机浏览只读取主机组和主机列表；凭据、网关选项改为打开管理表单时才请求，配置接口被拒绝不会阻断已授权主机的读取。并发刷新会合并，旧登录会话或旧列表请求的延迟响应不会覆盖新状态。该机制需要同步发布前后端；它不自动重放失败的写入、删除或执行请求。

K8s 集群管理独立读取已授权集群，不依赖网关和监控数据源配置权限。集群或 Namespace 授权均允许所属集群显示在列表中；普通成员点击名称进入对应集群概览，实际资源仍按授权范围过滤。新增、编辑及连接配置详情保留给平台管理员。撤销授权后会清除旧概览，延迟返回的旧请求不会恢复已撤销资源；集群暂时不可连接时，已授权集群选项仍保留。

## 用户组绑定授权

用户组卡片的“绑定授权”可同时选择多个已有访问策略，并绑定多个权限模板。策略绑定引用原策略的资源范围和操作，不复制记录；不重复绑定已直接授权给本组的策略。模板绑定必须选择资源类型、具体资源及可选 Namespace/索引，仅将模板对应操作应用到该范围；可为同一模板添加不同资源范围。

保存绑定时整组事务更新，取消不生效。来源修改、停用、删除以及解绑，会在下一次请求重新计算，页面通过权限版本自动更新。停用用户组或移出组员后不再继承。模板只读限制限定于绑定资源，不会赋予平台管理员身份，也不会扩大其他策略的范围。原直接授权保留，需在访问策略中单独编辑或撤销。

本次升级增加 `sys_group_access_binding` 表，需要一起更新前后端并重启后端执行 AutoMigrate。

## 已接入的资源范围

| 类型 | 范围 | 操作 |
| --- | --- | --- |
| 主机 | 指定主机或主机组及其所有下级组 | 查看、SSH、上传、下载、快速命令/脚本执行 |
| K8s | 指定集群；可进一步指定一个具体 Namespace | 查看、日志、Pod 终端/上传、重启、伸缩、变更、删除 |
| 数据库与已纳管中间件 | 连接实例（包含该连接可访问的库/Schema）；支持现有 MySQL、PostgreSQL、MongoDB、Redis 等类型 | 查看、查询、写入、导出、手动备份、恢复，受原有引擎能力限制 |
| 监控/日志数据源 | 指定数据源；Elasticsearch 可指定一个具体索引 | 查看、查询 |
| 凭据 | 指定凭据 | 查看脱敏信息、可选用、管理已有凭据 |

多个 Namespace 或索引应分别添加授权。空范围表示整个实例；不支持索引通配符、多个索引拼接或 `_all` 作为子范围。VictoriaLogs 按整个数据源授权。此版本不提供 SQL 表级权限、日志字段级过滤或 Kafka Topic 等尚未纳管对象的授权。

主机组授权在每次请求按现有树和成员展开，新加入组内的主机自动继承。主机、数据库、集群和数据源在 SQL 分页及计数之前过滤；详情和操作再次校验。批量命令会校验全部目标，包含无权主机时整体拒绝。文件分发分别校验源主机下载与目标主机上传权限。

SSH 授权遵循信任原则，只控制是否可以连接目标主机，不过滤主机内的命令。数据库仅查询授权使用数据库引擎的只读事务；写操作还需写入授权和原有风险确认。K8s Namespace 范围同时约束实际 Kubernetes 请求及跨 Namespace 列表，受限账号不使用共享概览缓存。

## 管理入口与间接访问

资源授权控制运行访问，不等同于平台配置管理。新增/修改主机和数据库连接、配置集群、云同步、用户和角色管理、备份计划配置等入口保留给超级管理员。角色页面及按钮授权本身不能绕过这个边界。

快速命令、脚本、文件分发已接入目标资源权限，执行历史限定为当前操作人。自动作业、流水线、AI 工具、服务诊断及其他未逐一接入授权的聚合/执行入口，目前只允许超级管理员使用，防止从间接入口绕过资源范围。新增后端接口必须在 `middleware/resource_access.go` 明确登记；未登记接口默认拒绝普通账号。

凭据仅返回脱敏资料；获准使用主机、数据库或集群时，平台可在连接层使用资源绑定的凭据，不要求再次授权查看其密码。资源授权页面不会公开密钥或 kubeconfig。

## 升级与验证

必须一起更新前后端并重启后端。启动时 AutoMigrate 增加 `sys_user_group`、`sys_user_group_member`、`sys_resource_grant` 三张表；`sys_resource_grant` 增加策略名称、启用标记、统一策略标记和模板来源，LDAP 配置增加默认用户组。菜单种子更新四个入口并停用部门和岗位菜单；保留现有用户、角色和角色菜单关系。

旧 `/system/role`、`/system/resource-access` 和 `/system/menu` 地址分别跳转到权限模板、访问策略和高级设置；部门和岗位旧页面跳转用户管理，其 API 已移除。部门/岗位模型、用户字段、个人资料显示和 LDAP 默认归属均不再使用；历史表和列保留，不执行破坏性删表。LDAP 新配置按普通成员创建账号，可自动加入默认用户组；旧默认角色配置以及已同步账号的权限保持兼容。

**普通账号不会自动获得全部资源。** 升级后先由超级管理员配置资源授权，再用普通账号验证；仅有原角色菜单权限的账号会看到空资源列表或操作被拒绝。超级管理员继续全量访问。

回归覆盖权限叠加、只读限制、具体 Namespace/索引、HTTP 功能与目标双重校验、混合批量目标、伪造 Content-Type、K8s 集合过滤、只读 SQL 事务、请求身份隔离和响应凭据脱敏。浏览器界面验证使用本地示例 API；未对线上资源做修改，也不代表已经完成真实 MySQL 迁移和真实 SSH/K8s/数据库连接的部署联调。
