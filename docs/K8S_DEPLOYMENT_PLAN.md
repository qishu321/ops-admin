# K8s 部署功能方案

日期：2026-10-27。状态：已按方案实现代码并进行隔离模拟验收；未操作现有服务数据或执行真实主机安装。

## 1. 目标与范围

在容器管理侧栏现有「K8s 管理」下方增加同级「K8s 部署」入口。入口进入部署计划列表，再通过「集群信息 → 高级配置 → 新增节点 → 信息确认」四步向导创建部署计划。

节点统一从 CMDB 主机管理关联，复用主机凭据和 SSH 网关。由 Ops Admin 后端调度部署执行器，经 SSH 安装 Kubernetes；不支持 Agent 部署，不展示执行模式，也不建设 Agent 服务。

部署计划保存安装参数、节点关系和执行记录；现有集群管理保存可访问的 Kubernetes 集群。安装成功后自动尝试接入集群管理，建立 plan → cluster 关联。

本功能是安装已有主机上的 Kubernetes，不负责创建云主机。首期不包含集群升级、卸载、重装、节点扩缩容、外置 etcd 或离线安装；这些可作为独立操作后续设计，不能由「删除部署记录」隐式触发。

## 3. 页面结构

### 3.1 菜单与路由

建议侧栏顺序：服务管理、服务健康诊断、K8s 管理、K8s 部署。

| 页面 | 建议路由 | 用途 |
| --- | --- | --- |
| 部署列表 | `/containers/k8s-deployments` | 搜索、状态、部署入口 |
| 新建部署 | `/containers/k8s-deployments/create` | 四步向导 |
| 编辑草稿 | `/containers/k8s-deployments/:id/edit` | 恢复草稿及修改配置 |
| 部署详情 | `/containers/k8s-deployments/:id` | 配置、节点、阶段进度、日志、运行历史 |

路由命名为建议，实施时与现有菜单匹配机制统一。详情和新建页不额外出现在侧栏。

### 3.2 部署列表

顶部为标题、用途说明、「新增部署」按钮和搜索区。保留 Ops Admin 当前卡片、表格及配色风格。

字段：部署名称、部署状态、Kubernetes 版本、控制平面/工作节点数量、集群接入状态、创建人、创建时间、描述、操作。

支持按名称、状态、版本筛选和分页。无需执行模式列。

操作随状态变化：草稿可编辑、预检、部署、删除；运行中可查看日志、请求停止；失败可查看原因并在核对节点状态后重试；成功可进入集群管理、查看历史。停止后保留现场，不承诺回滚；未确认远端进程退出前不得释放节点占用或开启下一次执行。

### 3.3 四步向导通用交互

顶部步骤条，底部固定操作区：上一步、下一步、保存草稿；最后一步为「确认并部署」。步骤切换保留输入，前进时校验本步骤，返回时保留已填内容。

草稿允许不完整配置；开始预检或部署时必须通过完整后端校验。部署开始后冻结本次运行的配置快照，避免修改列表字段影响正在执行的任务。

## 4. 第一步：集群信息

分为「基础配置」「网络配置」「节点初始化」三个区块，节点初始化可折叠，但确认页应完整展示。

| 字段 | 建议默认值与交互 | 规则 |
| --- | --- | --- |
| 部署名称 | 必填，最多 50 个字符 | 去除首尾空格；建议唯一；不直接用于 shell 或主机名 |
| Kubernetes 版本 | 可搜索下拉，并允许输入 `1.28.6` 形式 | 不含 v；校验格式和安装能力，格式正确不代表可以安装 |
| 容器运行时 | containerd | 版本由能力目录匹配，不使用不受控 latest |
| 自定义运行时数据目录 | 默认关闭；开启后出现路径输入 | 必须是允许的绝对路径，预检目录与磁盘情况 |
| 环境 | 默认从首台 CMDB 主机带入，也可手动选择 | 部署前必填，成功接入集群时继承 |
| 描述 | 可选 | 说明用途 |
| 网络插件 | Calico 为首期建议默认；目标支持 Flannel、Cilium | 插件及版本与 K8s、OS、内核组合校验 |
| Pod CIDR | `172.30.0.0/16` | 使用完整 CIDR 输入；允许粘贴，不锁死第三、四段 |
| Service CIDR | `10.254.0.0/16` | 与 Pod、主机子网及已知 VPC/路由网段不得重叠 |
| 节点网口 | `eth0` 作为初始提示 | 以真实探测为准；第三步允许逐节点覆盖 |
| 节点命名模式 | 建议默认保留主机名，也可自动命名 | 自动模式在第三步预览最终名称并校验合法性、唯一性 |
| 关闭 SELinux | 根据目标系统能力给出默认值 | 预检检测是否存在；不存在时标记不适用，不凭发行版名称判断 |
| Kubernetes 镜像仓库 | 可预填 `registry.cn-hangzhou.aliyuncs.com/google_containers` | 是可编辑初始值，实际部署前验证所需镜像可获取 |
| 自定义软件源 | 默认关闭；开启后显示编辑区 | 关联节点后按识别的 OS 校验 apt/yum/dnf 配置；受控写入并备份原配置 |
| 自定义配置 | 折叠的结构化 YAML 编辑区 | 限定 schema/允许字段；禁止覆盖节点、凭据、执行命令和平台生成的关键字段 |

「自定义源」负责安装包来源，「镜像仓库」负责镜像来源，两者独立；CNI、Metrics Server 镜像不保证来自 Kubernetes 基础镜像仓库，需要能力目录分别维护。

不设置操作系统选择项：目标节点是已有的 CMDB 服务器，系统从主机资产自动读取，在第三步及确认页只读展示。后台根据核验后的发行版、版本、架构自动匹配安装模板。第一步尚未关联节点时，系统相关选项标记为待节点关联后校验，不要求用户猜测或重复填写系统。

Pod/Service CIDR、网络插件等在部署开始后由本功能锁定；提示为「部署后本功能不支持修改」，避免把平台限制描述成 Kubernetes 永远不能变更。未知 VPC 网段应提示未覆盖的检查范围，不能显示为已确认无冲突。

自定义配置首期可先限定 kubelet 的少量常用参数。没有实现解析和渲染的字段不提供可保存但无效的入口。Rocky 主机重命名是否支持由实际适配验证决定，不照搬参考截图里的例外说明。

## 5. 第二步：高级配置

| 字段 | 交互与约束 |
| --- | --- |
| 高可用 | 默认关闭；首期非高可用为 1 个控制平面节点，高可用要求 3 个控制平面节点 |
| API 入口类型 | 高可用时选择「已有负载均衡」或「自建 HAProxy + Keepalived」 |
| API Server 地址 | 单控制平面可从所选节点推导；高可用必须配置稳定的域名/IP；自建时填写 VIP |
| API 入口端口 | 普通/外部 LB 默认 6443；自建 LB 建议 8443；与 kube-apiserver 后端 6443 明确区分 |
| virtual_router_id | 仅自建 LB 时显示；根据选定 Keepalived 版本校验范围；提示同网络中的冲突风险 |
| Kube-proxy 模式 | 首期 iptables；IPVS 在相应版本/内核适配验证后开放 |
| 自定义证书有效期 | 默认关闭；开启后显示叶证书与 CA 有效期；仅在所选 kubeadm 配置版本支持时开放 |
| Metrics Server | 可选，当前实现默认关闭；需要 kubelet 服务证书可信，由能力目录固定安装版本 |
| 控制平面运行普通业务 | 默认关闭；无工作节点的试验集群可显式开启 |

首期采用堆叠 etcd，不单独提供 etcd 角色选择。自建 LB 必须预检 VIP、网口、端口、节点网络和 VRRP 可用条件；网络条件不支持时要求使用已有 LB。已有 LB 模式只验证地址与转发，不代建云厂商负载均衡器。

证书有效期通过版本对应的 kubeadm 配置生成，不能把截图中的 UI 开关视为全版本支持。官方 v1beta4 配置提供 `certificateValidityPeriod` 和 `caCertificateValidityPeriod`，实施时转换 UI 单位并验证选定版本。

Cilium 的 kube-proxy replacement 作为后续独立能力；首期若开放 Cilium，限定经验证的运行方式，避免与 kube-proxy 选项组合失效。

## 6. 第三步：新增节点（关联 CMDB）

主操作为「从 CMDB 关联节点」。不在部署向导内再建一套主机、密码或密钥录入；缺少主机时提供跳转 CMDB 的入口，并保留部署草稿。

关联弹窗支持按主机名/IP、主机组、环境筛选和跨页多选。列出主机名、IP、OS/版本、CPU/内存、连接状态、凭据名称/认证类型、网关和是否可选。只返回当前用户有权限访问的资源，不返回密码、私钥。

已选节点表包括：主机名、部署 IP、节点名称、角色、系统、网口、认证类型、预检状态、移除操作。角色为控制平面（Master）/工作节点（Worker），支持批量设置角色；控制平面是否调度普通业务单独配置，不重复添加同一主机。

系统识别分两层：先读取 CMDB 已有的 OS、Arch、CPU、Memory、Disk 等信息用于展示和初步筛选；预检再通过 SSH 读取 `/etc/os-release`、实际架构及内核等信息，作为安装模板选择依据。当前 OS 字段为展示字符串，不直接当作可靠的结构化发行版/版本标识。资产信息缺失时可先关联，预检补充探测；探测失败或系统不受支持时阻断部署并给出原因。若实际结果与 CMDB 不一致，展示差异并使旧预检失效，核对后使用新快照，不静默修改执行配置。

多网卡主机需区分 SSH 连接地址与 Kubernetes 节点通信 IP；网口或部署 IP 不同于默认时在节点级覆盖，部署前验证其真实归属与互通。

节点约束：

- 至少 1 个控制平面节点；高可用按首期规则恰好 3 个；纯控制平面试验集群需要明确开启业务调度。
- 同一 CMDB 主机、同一真实主机身份不可重复关联；使用探测到的 machine-id 等辅助防止同机多资产记录绕过。
- 首期要求自动识别的 OS 家族、版本、架构符合已验证组合；混合系统/架构暂不支持。第三步直接提示不兼容节点，用户无需手动选择集群操作系统。
- 缺少有效凭据、必要权限、网关访问或被其他部署占用时禁止启动。
- CMDB 的在线状态只作参考，部署前重新做实际连通及权限预检。
- 发现已有 Kubernetes 安装/集群成员身份时阻止普通新建流程，不自动 reset。
- 保存 hostId 关系和非敏感快照；CMDB 修改 IP、凭据引用等后，旧预检失效并要求重新核对。

## 7. 第四步：信息确认

按基础信息、网络参数、初始化操作、高级配置、节点清单分组展示只读摘要。每组提供「修改」返回对应步骤。显示控制平面/工作节点数量及最终主机名、网口、部署 IP。

确认页明确列出将执行的变更：安装软件包、修改内核参数/主机名/软件源、配置 containerd、处理 SELinux 等。敏感信息只显示凭据名称和认证方式，不展示秘密。

提供「执行预检」和预检报告；阻断项修复前不能开始部署。预检只执行探测，不安装软件、不修改系统配置。草稿可以随时保存。

预检覆盖：SSH 和网关、root/sudo 能力、OS/内核/架构、CPU/内存/磁盘、时间同步、swap 和内核条件、节点名称、网口/IP、端口、节点间通信、软件源及镜像访问、CIDR 冲突、现有 Kubernetes 痕迹、高可用入口条件。

结果分为通过、警告、阻断。资源下限及网络检测项来自所选部署配置，而非页面写死。预检报告绑定计划版本、主机快照、执行器版本和有效期；参数变化后失效。点击「确认并部署」时重新鉴权、校验预检并原子占用节点，返回任务 ID 后跳转详情。

## 8. 安装执行与详情

推荐自有轻量部署编排器 + 版本化 kubeadm 配置/安装模板，复用当前 SSH 与网关连接能力。首期无需引入独立消息队列，可用数据库持久化任务加 worker 领取机制，但必须有租约、并发控制和恢复核对。

执行顺序：

1. 锁定配置快照、再次校验节点身份和权限。
2. 准备节点系统与软件源，记录原配置备份。
3. 安装并配置 containerd、kubeadm、kubelet、kubectl。
4. 按配置准备 API 入口，初始化第一个控制平面节点。
5. 安装 CNI，并等待必要组件状态。
6. 顺序加入其余控制平面节点，受控并发加入 Worker。
7. 安装可选 Metrics Server。
8. 核验 API、节点 Ready、CoreDNS/CNI 及启用的组件。
9. 安全获取 kubeconfig，尝试接入 Ops Admin 集群管理。

具体安装驱动、OS 模板和版本矩阵需在实施前用测试主机验证；本方案不承诺兼容所有可手动输入的版本。

详情页分「执行概览」「节点状态」「配置快照」「实时日志」「运行历史」。阶段显示状态、起止时间和失败原因；日志可按节点、阶段过滤，并通过游标增量读取支持断线恢复。整体进度按阶段展示，不伪造预计完成时间。

部署状态建议：草稿、预检中、待部署、排队中、部署中、停止中、已停止、失败、待核对、成功。接入状态单独记录：未接入、接入中、已接入、接入失败。

停止或执行器租约丢失不代表远端安装进程已经退出。服务重启后先核对任务、远端进程和集群状态；无法确认时进入「待核对」，不得盲目重跑 init/join。重试创建新 run，保留历史，依据已完成阶段及实际节点状态决定续跑，不做通用的一键全量重装。

## 9. 与现有集群管理衔接

安装成功后获取 kubeconfig，按现有集群登记服务做连接校验，再写入 `k8s_cluster` 并关联 clusterId。继承名称、环境和描述；登记必须幂等，重试时不能生成重复集群。

接入路径需要从 Ops Admin 服务端验证，而不只是从安装节点验证。SSH 网关可达主机不等于平台可直连 API Server，必要时复用现有集群连接网关配置，并在确认页说明接入路径。

若安装成功但平台接入失败，保留「部署成功 / 接入失败」，提供「重新接入」。接入失败不得触发重新安装。CMDB 通过关系记录展示所属集群、节点角色和 Kubernetes 节点名；不能依靠 IP 猜测所有权。

删除草稿只删除计划；对已经执行的记录建议归档。删除或归档部署记录不卸载节点上的 Kubernetes，也不自动删除已有集群登记。

## 10. 数据与接口建议

新增四类核心记录：

| 模型 | 关键内容 |
| --- | --- |
| `k8s_deploy_plan` | 名称、配置 JSON/schemaVersion、版本号、状态、创建人、clusterId、接入状态 |
| `k8s_deploy_node` | planId、hostId、角色、部署 IP、节点名、网口覆盖、非敏感主机快照 |
| `k8s_deploy_run` | planId、配置快照、模板/执行器版本、预检报告、状态、租约、开始结束时间、失败摘要 |
| `k8s_deploy_step` | runId、hostId（可空）、阶段、尝试次数、状态、退出码、日志游标/位置 |

节点占用需另有可事务获取的唯一 hostId 锁/归属记录。运行中保持锁；失败或停止后核对现场再释放执行锁，已属于集群的主机仍不可被新建计划重用。预检 run 与部署 run 分类型记录。

日志独立分块存储，设置容量与保留期；不把无限增长的全量 stdout 塞入计划表。普通配置保存凭据引用，执行时按当前授权解析；密钥与 kubeconfig 使用受控的加密存储及访问路径，不进入普通日志/配置 JSON。现有 kubeconfig 字段应评估兼容读写与加密迁移，不能仅在新表加密后又明文复制到集群表。

接口按现有风格建议使用 `/k8s/deploy/...` 前缀：

| 接口 | 方法 | 作用 |
| --- | --- | --- |
| `/capabilities` | GET | 可用版本、OS、插件和字段能力 |
| `/list`、`/info` | GET | 列表、详情 |
| `/create`、`/update` | POST / PUT | 保存、编辑草稿 |
| `/host-options` | GET | 按授权返回 CMDB 主机和可选原因 |
| `/precheck` | POST | 提交预检任务 |
| `/start` | POST | 校验计划版本/预检、占用主机、创建部署 run |
| `/runs`、`/run/detail` | GET | 运行历史、步骤与节点状态 |
| `/logs` | GET | 按 run、节点、阶段、游标读取日志 |
| `/stop`、`/retry` | POST | 请求停止、核对后重试 |
| `/register-cluster` | POST | 仅重试集群接入 |
| `/delete`、`/archive` | DELETE / POST | 删除草稿或归档历史 |

启动、重试、接入均要求幂等键；编辑采用版本号避免多人覆盖。运行中的配置不允许通过 update 修改。

权限建议独立定义部署的查看、创建/编辑、预检、执行、停止、重试、日志读取、归档，以及接入集群的权限。沿用现有主机资源授权和只读限制；提交 hostId、查询日志、执行异步任务、自动接入都要校验相应范围。预检权限也涉及远程执行，不能等同于普通列表查看。记录操作者、配置差异、目标主机、启动/停止/重试和结果。

## 11. 实施顺序和验收

以下是交付顺序建议，不删除完整需求；尚未适配的能力在页面明确禁用或暂不展示。

**第一阶段：形成可审阅的业务流程。** 菜单、部署列表、四步向导、能力目录、CMDB 关联、草稿与确认摘要；后端完成配置校验和权限。此阶段尚不能宣称能安装真实集群。

**第二阶段：交付首个真实部署闭环。** 优先验证一种实际使用的 OS/Kubernetes 组合，containerd + Calico + 单控制平面；加入只读预检、持久任务、阶段日志、失败处理、自动集群接入。支持通过现有 SSH 网关访问目标主机。

**第三阶段：补全高级能力。** 3 控制平面高可用、已有 LB/自建 LB、其他 OS、Flannel/Cilium、IPVS、自定义软件源及受控配置。按实际支持矩阵逐项验收，不一次性宣称支持所有组合。Agent 不在任何阶段范围内。

验收重点：

- 菜单位于 K8s 管理下方；界面不存在 Agent、执行模式或手动操作系统选择字段。
- 关联主机后自动展示 CMDB 配置；预检核验实际系统并匹配安装模板，覆盖信息缺失、资产信息过期及不支持系统场景。
- 四步切换、草稿恢复、最终摘要一致；CMDB 过滤和角色设置正确。
- 后端拒绝非法 CIDR、重复节点、缺失控制平面、未支持版本、过期预检、越权 hostId。
- 重复点击部署只创建一个有效运行；同一主机不能并行参与两个安装。
- 在专用测试主机完整安装成功，节点及核心组件就绪，集群管理可访问。
- 安装失败、SSH 中断、服务重启和停止场景可查看真实状态，不盲目重装或释放节点。
- 自动登记失败后可以只重试接入；历史配置、日志保留且不泄露凭据。
- 高可用上线时另做控制平面/API 入口故障切换验证；不同 OS 和网络插件分别验证。

## 12. 当前实现与验证范围

已实现菜单、部署列表、四步向导、草稿与版本校验、CMDB 分页多选、只读系统识别、SSH 预检、持久化运行/步骤/增量日志、主机占用、停止请求、心跳中断保护、集群自动登记及单独重试接入。安装通过 SSH 复用现有凭据和网关；部署生成的 kubeconfig 加密保存，并兼容现有集群连接解析。

当前安装模板覆盖 Ubuntu 22.04/24.04、Debian 12/13，x86_64/aarch64，Kubernetes 1.31.x–1.34.x、containerd、Calico/Flannel；包含单控制平面、三控制平面、已有 LB 和 HAProxy + Keepalived 配置。Cilium 显示为待适配，不接受提交。目标主机需预装 python3、iproute2、systemd，具备 root 或无交互 sudo 权限和必要的联网条件；现有 Kubernetes/运行时数据会阻断新建安装。不同系统/架构混用暂不支持。

安装发生变更后的失败或中断进入待核对，保留主机归属，不提供盲目重装或自动 reset。尚未提供扩缩容、卸载、升级、离线安装、历史归档与自动日志保留期管理。

验证包括 Go 自动化测试、生成 Bash/Python 脚本的语法校验、前端构建和浏览器模拟关键路径。模拟服务为 `web/tests/fixtures/k8s-deploy-server.mjs`，监听 `127.0.0.1:18081`，仅使用内存数据，不具备代理、数据库或 SSH 能力。没有对 `127.0.0.1:8080` 写入数据，也没有启动/重启连接现有数据库的后端；真实安装和故障切换尚需在专用测试主机验收。
